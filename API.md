# TVmaze API - конспект

Документація: <https://www.tvmaze.com/api>. Базовий URL: `https://api.tvmaze.com`.
Усі перевірки виконано 22.10.2026 з `http://127.0.0.1:8099/experiments.html` (Chromium, панель Network)
і продубльовано `curl` для читання заголовків, яких скрипт не бачить через CORS.

| Питання | Що каже документація | Що показав запит (адреса) |
|---|---|---|
| Ендпоїнт пошуку за назвою, параметри | `GET /search/shows?q=:query`. Параметр `q` обов’язковий; пошук нечіткий (fuzziness 2), результати відсортовані за релевантністю. Є окремий `GET /singlesearch/shows?q=:query` - один результат або жодного, з підтримкою `embed` | `https://api.tvmaze.com/search/shows?q=girls` → `200`, 10 елементів, перший - `Girls` (id 139). `https://api.tvmaze.com/singlesearch/shows?q=girls` - той самий серіал одним об’єктом |
| Форма відповіді пошуку | Документація описує лише «кожен елемент містить повну інформацію про серіал»; точної схеми немає | `https://api.tvmaze.com/search/shows?q=girls` → масив об’єктів `{score, show}`; `score` - число від 0 до 1 (у першого `0.88683844`), `show` - повний об’єкт серіалу з 23 полями: `id, url, name, type, language, genres, status, runtime, averageRuntime, premiered, ended, officialSite, schedule, rating, weight, network, webChannel, dvdCountry, externals, image, summary, updated, _links` |
| Ендпоїнт серіалу; як отримати епізоди й акторів одним запитом | `GET /shows/:id`; вбудовування через `embed`, кілька зв’язків - синтаксисом масиву: `?embed[]=episodes&embed[]=cast`. Окремо існують `/shows/:id/episodes` і `/shows/:id/cast` | `https://api.tvmaze.com/shows/82?embed[]=episodes&embed[]=cast` → `200`; у відповіді з’являється `_embedded` з `episodes` (73) і `cast` (42). Перший епізод - S1E1 «Winter is Coming», перший актор - Peter Dinklage / Tyrion Lannister |
| Поля серіалу, що можуть бути `null` (з прикладом серіалу) | Розділ Images: якщо зображення немає, `image` - `null`. Інші поля документація окремо не застерігає | `https://api.tvmaze.com/shows/5083` («Melt Ya Face») → `image: null`, `rating.average: null`, `officialSite: null`, `webChannel: null`. `https://api.tvmaze.com/shows/5003` → `summary: null`; `https://api.tvmaze.com/shows/5215` → `premiered: null` (і `ended: null`) |
| Що повертає пошук без результатів | Не описано | `https://api.tvmaze.com/search/shows?q=zzzzqqqxyz` → `200`, тіло `[]` (порожній масив), `Content-Type: application/json; charset=UTF-8`. Помилки немає - це саме «нічого не знайдено», а не збій |
| Що повертає неіснуючий id | Для `lookup` і `episodebynumber` документація згадує `404`; для `/shows/:id` формат помилки не описано | `https://api.tvmaze.com/shows/999999999` → `404`, `Content-Type: application/json`; тіло `{"code":0,"message":"","name":"Not Found","status":404}`. `response.ok === false`, але проміс `fetch` не відхиляється |
| Ліміт запитів і що робити на 429 | «At least 20 calls every 10 seconds per IP»; при перевищенні - `HTTP 429`; клієнт має почекати кілька секунд і повторити; ліміт може тимчасово бути суворішим; тримати не більше одного з’єднання | 60 запитів двома пачками по 30 паралельних (унікальні `/search/shows?q=zzprobe<timestamp><i>` і `/shows/1…30?probe=<timestamp>`) → `200`, крім одного `404` на неіснуючий id. `429` не сталося: «at least 20 calls every 10 seconds» - це гарантований мінімум, а не точний поріг, і фактичний ліміт виявився вищим, тобто ми його не перетнули. Адреса прикладу: `https://api.tvmaze.com/search/shows?q=zzprobe<timestamp>0`. `Retry-After` скрипт не побачить: TVmaze не надсилає `Access-Control-Expose-Headers` (curl на `/shows/82`, `/search/shows`, `/shows/5083`), у `response.headers` лише `cache-control` і `content-type` (експеримент 7), тому інтерфейс має орієнтуватися на `status === 429` і власну паузу |
| Кешування: що кешує TVmaze і що - браузер | Усі відповіді кешують балансувальники на 60 хвилин; `/schedule/full` і `/shows?page=` - до 24 годин | `https://api.tvmaze.com/shows/82` → заголовок `cache-control: public, max-age=3600` (curl і Network показують однаково). Тобто браузер має право 3600 с віддавати відповідь без запиту; експеримент 8 це підтвердив: 779 мс перший запит, 6 мс другий, 281 мс із `cache: 'no-store'` |
| CORS: що обіцяє документація і що показав експеримент 12 | «All endpoints are CORS enabled» - тобто API можна викликати прямо з браузера без проксі | `https://api.tvmaze.com/shows/82` з `Accept: application/json` → `200` і `access-control-allow-origin: *`; простий GET працює. Але preflight `OPTIONS https://api.tvmaze.com/shows/82` з `Access-Control-Request-Headers: content-type` → `405` з `allow: GET, HEAD` і без `Access-Control-Allow-Origin`, тому GET із `Content-Type: application/json` браузер блокує ще до відправлення. Отже «CORS enabled» стосується лише простих запитів |
| Ліцензія й атрибуція | Дані за CC BY-SA: вільне використання з обов’язковим посиланням на TVmaze як джерело і збереженням ShareAlike | `https://api.tvmaze.com/shows/82` → у тілі є `url: "https://www.tvmaze.com/shows/82"` і `_links.self.href` на ту саму сторінку; саме це посилання використано в атрибуції у footer ShowFinder |

## Що з цього важливо для коду застосунку

- `response.ok` перевіряти обов’язково: `404` приходить як звичайна відповідь із JSON-описом помилки (`name: "Not Found"`).
- Порожній пошук - це `200` і `[]`: окремий стан «нічого не знайдено», не помилка.
- `image`, `rating.average`, `premiered`, `ended`, `summary`, `officialSite`, `webChannel` можуть бути `null` - шаблони мають це витримувати.
- Епізоди й актори беруться одним запитом через `embed[]`, а не двома-трьома послідовними.
- `429` обробляти за статусом, з паузою; `Retry-After` для чужого домену недоступний.
- Власний кеш застосунку не замінює HTTP-кеш, але й покладатися лише на `max-age=3600` не можна: після закінчення години дані знову підуть у мережу.
- Ніяких `Content-Type` у GET і жодних `mode: 'no-cors'` - це або блокує запит, або перетворює відповідь на порожню.
